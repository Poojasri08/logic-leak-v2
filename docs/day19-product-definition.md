Day 19 – Product Definition



1\. Problem



Many beginners learn web security through theory and individual labs, but they may find it difficult to identify vulnerabilities in application code and understand how to fix them.



Logic Leak 2.0 is designed to make security learning more practical through an interactive challenge-based workflow.



2\. Target Users



\* Cybersecurity beginners

\* Students learning Web and API Security

\* Students preparing for WAPT, VAPT, and AppSec roles



3\. Product Statement



Logic Leak 2.0 is an interactive secure-code-learning platform where users identify vulnerabilities, explain the security issue, apply the correct fix, and earn progress through challenges.



4\. Current Product Flow



Login → Challenge → Find the Leak → Explain → Fix → Earn XP → Progress → Next Challenge



5\. Current Security Baseline



The application currently includes security controls and testing for:



\* Authentication

\* Authorization

\* JWT validation

\* Input validation

\* Challenge progression enforcement

\* Tier enforcement

\* Duplicate reward prevention

\* Invalid JSON handling

\* Cross-user access testing

\* Security regression testing

\* Repository hardening



6\. Current Challenges



Challenge 1 – Bank Transfer



\* SQL Injection

\* Negative transfer amount validation

\* Parameterized query / prepared statement



Challenge 2 – Product Search



\* Web application security vulnerability identification and remediation



Challenge 3 – E-commerce Checkout



\* Web application security vulnerability identification and remediation



7\. Core Learning Approach



Logic Leak 2.0 does not focus only on finding a vulnerability.



The learning flow is:



Identify → Explain → Fix → Verify



This helps the learner understand both the security problem and the secure development approach.



8\. Future Features



Planned improvements include:



\* XP and streak system

\* Leaderboard

\* More security challenges

\* Difficulty progression

\* Achievements

\* Additional Web and API security scenarios



These features will be added based on user feedback rather than adding features only for the sake of increasing the project size.



9\. Validation Plan



The next stage is to validate the existing product with a small group of students.



The validation will focus on:



\* Whether users understand the challenge flow

\* Whether the instructions are clear

\* Where users get stuck

\* Whether users can identify the vulnerability

\* Whether users understand the required fix

\* Whether the progression system is understandable



The feedback will be used to decide the next development priorities.



10\. Current Goal



The goal of the next stage is to move Logic Leak 2.0 from a security-focused project into a usable cybersecurity learning product.



The priority is usability and validation before adding unnecessary features.
